Univariate forecasters

All models share a consistent interface — each accepts a target_col to specify the target series, along with any model-specific parameters. Fitting is done via .fit(df) and forecasting via .forecast(H). Exogenous variables, where supported, are passed at the forecasting step and aligned automatically. All models also expose .cross_validate() for evaluation, supporting both expanding and sliding window strategies with a configurable step size.

The table below summarises the available univariate forecasters, from simple baselines to statistical and machine learning models, along with a minimal usage example for each.

Usage example

Regardless of whether you use ETS, ARIMA, a machine learning regressor, or any other supported model, the interface is consistent. The .forecast(H) method returns a consistent numpy array of forecasts, and the .cross_validate() method provides a standardized way to evaluate model performance across different time series and forecasting horizons.

  • Index of data: A DatetimeIndex (or RangeIndex) is required for all models to ensure proper time series handling and forecasting. The index is recommended to be at a regular frequency without any missing timestamps.

  • Target column: The target_col parameter specifies the name of the column in the input DataFrame that contains the time series to be forecasted.

Example usage for different models are provided in cells below, demonstrating how to fit and forecast with each model type using the same dataset and target column for consistency.

Automatic Model Selection with auto_arima

auto_arima automates ARIMA and SARIMA order selection using the Hyndman-Khandakar (2008) stepwise search algorithm and repeated KPSS stationarity tests. You can inspect the top candidate models with .top_models(n) and extract parameter dictionaries for any candidate rank using .get_orders(rank=k) or .best_orders.

from peshbeen.models import auto_arima

# Stepwise automatic model selection
auto_model = auto_arima(target_col='passengers', seasonal_length=12, max_p=3, max_q=3, max_P=2, max_Q=2, stepwise=True)
auto_model.fit(train_data)

# Summary and top candidates
print(auto_model.summary())
print('\nTop 3 candidate models:')
display(auto_model.top_models(3))

# Multi-step out-of-sample forecast
auto_forecast = auto_model.forecast(H=12)
print('\nSelected Best Parameters:', auto_model.best_orders)

Direct Multi-Step Forecasting with ml_direct_forecaster

Standard machine learning forecasters (ml_forecaster) use a recursive strategy: they predict horizon \(h=1\), append that prediction as a new lag, and step forward iteratively to predict \(h=2, 3, \dots, H\). While flexible, recursive forecasting can accumulate prediction errors over long horizons.

ml_direct_forecaster uses a direct multi-step strategy: it trains a dedicated regressor for each individual horizon step \(h \in \{1, \dots, H\}\). Each model is optimized specifically for its forecast lead time directly from observed historical features, preventing error compounding.

from peshbeen.models import ml_direct_forecaster
from peshbeen.datasets import load_airline_passengers
from lightgbm import LGBMRegressor

pax = load_airline_passengers()
pax_train = pax[:-12]
pax_test = pax[-12:]

# Direct forecaster: trains independent models, one per horizon step up to H=12
direct_model = ml_direct_forecaster(
    model=LGBMRegressor(n_estimators=50, random_state=42, verbose=-1),
    target_col='passengers',
    H=12,
    lags=12
)
direct_model.fit(pax_train)
direct_fc = direct_model.forecast(H=12)

print("Direct ML forecasts (H=12):", direct_fc[:5])
Direct ML forecasts (H=12): [385.82705361 392.99494058 419.0278088  420.87151715 432.4001238 ]

Forecasting with MS-ARR: Capturing Regime Changes

Models like ARIMA or Random Forest assume the “rules” of a time series are constant. However, real-world data often undergoes structural shifts—moving between a high-volatility “crisis” mode and a stable “growth” mode.

While the models above assume a stable relationship over time, real-world data sometimes exhibits regime changes. Peshbeen includes native support for MS-ARR to model these “regime changes” (e.g., shifting from a high-volatility to a low-volatility state) explicitly. MS-ARR models capture these dynamics by allowing the time series to switch between different hidden regimes, each with its own autoregressive structure.

How it Works: The Hidden Dynamics

The AR-MSR model in peshbeen is defined by four core components:Regime-Dependent Dynamics: In each regime \(r\), the process follows a unique autoregressive structure:

\[ y_t \mid (r_t = r) = \beta_{0}^{(r)} + \sum_{i=1}^{p} \beta_{i}^{(r)} y_{t-i} + \sum_{m=1}^{M} \beta_{m}^{(r)} X_{tm} + \epsilon_t, \quad \epsilon_t \sim \mathcal{N}(0, \sigma_r^2) \]

\(y_t\) is the target variable at time \(t\), \(X_{tm}\) are optional exogenous variables, and \(\epsilon_t\) is the error term. The intercept (\(\beta_0\)), coefficients (\(\beta_i\)), and volatility (\(\sigma_r^2\)) all adapt to the specific regime.

Transition Probability Matrix (\(\mathbf{P}\)): The model learns the probability of moving from one regime to another. For a 2-regime model, the matrix \(\mathbf{P}\) looks like this:

\[ \mathbf{P} = \begin{pmatrix} p_{11} & p_{12} \\ p_{21} & p_{22} \end{pmatrix} \]

where \(p_{ij}\) is the probability of transitioning from regime \(i\) to regime \(j\). This captures the “stickiness” of states (e.g., how likely a recession is to continue into the next period).

Estimation via EM (Expectation-Maximization) Algorithm: The model parameters are estimated using the EM algorithm, which iteratively refines estimates of the hidden states and the model parameters until convergence. Under the hood, peshbeen calculates the transition matrix and the filtered probabilities (the likelihood of being in a state at any given time) using the Baum-Welch algorithm. This uses a Forward-Backward pass to efficiently find the Maximum Likelihood Estimates (MLE) for the hidden Markov process.

The Markov Property: Transitions depend only on the current state, not the entire history. This allows the model to remain computationally efficient even as the complexity of the data increases.

Why use MS-ARR in Peshbeen?

  • Capture Non-Linearity: It models complex shifts that ARIMA or standard ML models might miss.

  • Regime Inference: Use model.predict_states() to see a historical timeline of when your series was likely in each regime. Use model.predict_proba() to get the probability of being in each regime at any point in time.

  • Adaptive Forecasting: The forecast accounts for the probability of a regime shift occurring during the forecast horizon \(H\).

## Create a sales series with regime switches
import numpy as np
import pandas as pd

np.random.seed(42)
n = 300
dates = pd.date_range(start="2000-01-01", periods=n, freq="ME")

# Define hidden regimes (Regime 0 is "Stable", Regime 1 is "High")
regime_switches = np.zeros(n)
for i in range(1, n):
    # Create persistent regimes (90% chance to stay in current state)
    if regime_switches[i-1] == 0:
        regime_switches[i] = np.random.choice([0, 1], p=[0.9, 0.1])
    else:
        regime_switches[i] = np.random.choice([0, 1], p=[0.2, 0.8])

series = np.zeros(n)
# Generate data with AR(1) logic based on the current regime
for t in range(1, n):
    if regime_switches[t] == 0:
        # Regime 0: Low mean, high lag dependency
        series[t] = 5 + 0.8 * series[t-1] + np.random.normal(0, 1)
    else:
        # Regime 1: High mean, low lag dependency
        series[t] = 25 + 0.2 * series[t-1] + np.random.normal(0, 3)

ms_data = pd.DataFrame({"sales": series}, index=dates)

train_ms =  ms_data.iloc[:-30]
test_ms = ms_data.iloc[-30:]

from peshbeen.models import ms_arr
ms_arr_model = ms_arr(target_col="sales", n_components=2, lags=2, add_constant=True, n_iter=50, tol=1e-4, random_state=42)
ms_arr_model.fit(train_ms)
ms_arr_forecast = ms_arr_model.forecast(H=30)

regime_probs = ms_arr_model.predict_proba()

## also  create linear regression forecasts for comparison
from sklearn.linear_model import LinearRegression
lr_model = ml_forecaster(target_col="sales", model=LinearRegression(), lags=2)
lr_model.fit(train_ms)
lr_forecast = lr_model.forecast(H=30)

import matplotlib.pyplot as plt

fig, ax1 = plt.subplots(figsize=(14, 7))

# Get regime probabilities
regime_probs_train = ms_arr_model.predict_proba()
# `forecast_forward` is populated by the .forecast(H) call above: an (n_regimes, H) array of
# regime probabilities over the forecast horizon. Row 0 -> Regime 0, row 1 -> Regime 1.
regime_probs_forecast = ms_arr_model.forecast_forward

# No lag offset needed - already aligned with full training data!
n_train_tail = 100

# Get tail of training data and regime probs
train_dates_tail = train_ms.index[-n_train_tail:]
train_sales_tail = train_ms["sales"].values[-n_train_tail:]
regime_probs_tail = [regime_probs_train[0][-n_train_tail:], 
                     regime_probs_train[1][-n_train_tail:]]

# Combine with forecast
dates_full = list(train_dates_tail) + list(test_ms.index)
regime_probs_full = [np.concatenate([regime_probs_tail[0], regime_probs_forecast[0]]),
                     np.concatenate([regime_probs_tail[1], regime_probs_forecast[1]])]

# Plot the time series on primary axis
ax1.plot(train_dates_tail, train_sales_tail, 
         label="Train", color="C0", linewidth=2)
ax1.plot(test_ms.index, test_ms["sales"], 
         label="Test (Actual)", color="C1", linewidth=2)
ax1.plot(test_ms.index, ms_arr_forecast, 
         label="MS-AR(2) Forecast", color="C2", linestyle='--', linewidth=2)
ax1.plot(test_ms.index, lr_forecast, 
         label="Linear Regression Forecast", color="C3", linestyle='--', linewidth=2)

ax1.set_ylabel("Sales", fontsize=12)
ax1.set_xlabel("Date", fontsize=12)
ax1.legend(loc="upper left", fontsize=10)
ax1.grid(True, alpha=0.3)

# Overlay regime probabilities as stacked area
ax2 = ax1.twinx()
ax2.stackplot(dates_full,
              regime_probs_full[0], 
              regime_probs_full[1],
              labels=['Regime 0', 'Regime 1'], 
              alpha=0.25, 
              colors=['C2', 'C3'])

ax2.set_ylabel("Regime Probability", fontsize=12)
ax2.set_ylim(0, 1)
ax2.legend(loc="upper right", fontsize=10)

plt.title("Markov Switching AR(2) with Regime Probabilities", fontsize=14, fontweight='bold')
plt.setp(ax1.get_xticklabels(), rotation=45, ha="right")
plt.tight_layout()
plt.show()

Forecasting count data with a GLM (Poisson)

For non-negative count series — hospital admissions, call volumes, demand — a Poisson (or Gamma) GLM is often a better fit than a Gaussian model. peshbeen’s glm wraps statsmodels and takes a family object (not a string), e.g. sm.families.Poisson() for counts or sm.families.Gamma() for strictly positive, skewed data. It supports the same lags / difference / trend / box_cox interface as the other models, and exposes information criteria (.aic, .bic, .hqc) for model comparison.

from peshbeen.models import glm
import statsmodels.api as sm
import matplotlib.pyplot as plt
import pandas as pd

## generate a counted series with calendar effects and lags, to demonstrate Poisson GLM
df_count = pd.DataFrame({"count": np.random.poisson(lam=10, size=200)}, 
                        index=pd.date_range(start="2020-01-01", periods=200, freq="D"))
df_count["day_of_week"] = df_count.index.dayofweek
df_count["month"] = df_count.index.month
glm_cat = ["day_of_week", "month"]
# daily emergency-admission counts in Wales
glm_cat = ["day_of_week", "month"]

glm_train = df_count.iloc[:-30]
glm_test = df_count.iloc[-30:]

from sklearn.preprocessing import OneHotEncoder
ohe = OneHotEncoder(drop='first', sparse_output=False, handle_unknown="ignore")

# Poisson GLM for count data, with weekly lags and calendar features
poisson_model = glm(family=sm.families.Poisson(), target_col="count",
                    lags=6, cat_variables=glm_cat, categorical_encoder=ohe)
poisson_model.fit(df_count)
poisson_forecast = poisson_model.forecast(H=30, exog=df_count[glm_cat])


plt.figure(figsize=(12, 6))
plt.plot(df_count.index[-90:], df_count["count"][-90:], label="Train")
plt.plot(df_count.index[-30:], df_count["count"][-30:], label="Test")
plt.plot(df_count.index[-30:], poisson_forecast, label="Poisson GLM Forecast")
plt.title("Poisson GLM forecast of daily counts")
plt.xlabel("Date")
plt.ylabel("Counts")
plt.legend()
plt.show()

Combining models with the pesh ensemble

pesh combines several fitted models behind the same .fit / .forecast interface. The combination weights can be equal (weighting_scheme=None), user-specified (a dict that sums to 1), or optimised to minimise a chosen metric. To optimise the weights, call cross_validate(..., weighting_scheme="optimize") — the optimal weights are then stored in self.optimal_weights_ and can be passed back into a new pesh instance. forecast(H) returns a DataFrame with one column per member model plus a combined "pesh" column.

from peshbeen.models import ets, arima, ml_forecaster, pesh
from peshbeen.datasets import load_airline_passengers
from peshbeen.metrics import RMSE
from lightgbm import LGBMRegressor

pax = load_airline_passengers()
pesh_train = pax[:-12]
pesh_test = pax[-12:]

# build the member models (note: ml_forecaster uses model=, not estimator=)
members = {
    "ets":   ets(target_col="passengers", seasonal="additive", trend="additive",
                 seasonal_periods=12, smoothing_level=0.5, smoothing_trend=0.5, smoothing_seasonal=0.5),
    "arima": arima(target_col="passengers", order=(1, 1, 1), seasonal_order=(1, 1, 1), seasonal_length=12),
    "lgbm":  ml_forecaster(target_col="passengers",
                           model=LGBMRegressor(n_estimators=100, random_state=42, verbose=-1),
                           difference=1, lags=12),
}

# 1) optimise the ensemble weights via cross-validation, then read them back
weight_finder = pesh(models={k: m.copy() for k, m in members.items()})
cv_results = weight_finder.cross_validate(df=pesh_train, cv_split=3, test_size=12,
                                          metrics=[RMSE], weighting_scheme="optimize")
opt_weights = weight_finder.optimal_weights_
# optimal_weights_ also contains a "pesh" key for the combined column; keep only member weights
opt_weights = {k: v for k, v in opt_weights.items() if k in members}
print("Optimised weights:", opt_weights)

# 2) fit a fresh ensemble with the optimised weights and forecast
ensemble = pesh(models=members, weighting_scheme=opt_weights)
ensemble.fit(pesh_train)
ensemble_forecast = ensemble.forecast(H=12)   # DataFrame: one column per model + 'pesh'

import matplotlib.pyplot as plt
plt.figure(figsize=(12, 6))
plt.plot(pesh_train.index[-36:], pesh_train["passengers"][-36:], label="Train")
plt.plot(pesh_test.index, pesh_test["passengers"], label="Test")
plt.plot(pesh_test.index, ensemble_forecast["pesh"], label="pesh ensemble", linewidth=2)
for name in members:
    plt.plot(pesh_test.index, ensemble_forecast[name], linestyle="--", alpha=0.6, label=name)
plt.title("Weighted ensemble (pesh) vs. its members")
plt.xlabel("Date")
plt.ylabel("Passengers")
plt.legend()
plt.show()
Optimised weights: {'ets': np.float64(0.0), 'arima': np.float64(1.0), 'lgbm': np.float64(6.228351168147128e-14)}

Multivariate forecasters

Differentiating Forecasters Across Multiple Series:

  • Wide Multivariate Forecasters (ml_multi_output_forecaster, var, ms_var):
    • Data format: Expect wide format data — a DataFrame where each column is an endogenous target series (target_cols = ['series_1', 'series_2', ...]) sharing identical timestamps on a common DatetimeIndex.
    • Mechanism: Model simultaneous feedback, cross-variable lag interactions, and joint system dynamics where past values of series A directly inform series B and vice versa.
    • Trade-offs: Highly effective for capturing rich feedback loops between a small-to-moderate set of interdependent series (e.g., price and demand, interest rate and inflation). However, because feature dimensionality scales with \(K \times L\) (number of series \(\times\) lags), wide models are not intended for scaling to hundreds or thousands of series.
  • Multi-Series Forecasters (panel_forecaster, ml_multi_forecaster):
    • Data format: Expect long (panel) format data — a DataFrame with an entity ID column (id_col), a target column (target_col), and timestamps.
    • Mechanism & Scaling: Discussed in detail in the Multi-series section below.
Models Description Usage Example

model = ml_multi_output_forecaster(RandomForestRegressor(), target_cols=[‘interest’, ‘inflation’], lags=4)
model.fit(df)
fc = model.forecast(H=12)

model = var(target_cols=[‘col1’, ‘col2’], lags={‘col1’: 2, ‘col2’: [1, 2, 7]})

Example for multivariate forecasting works using the VAR model.

Peshbeen’s VAR model allows you to specify different lag structures for each target series, enabling you to capture the unique temporal dependencies of each series while modeling their interdependencies. Different than the implementation of the standard VAR in statsmodels, which applies the same lag structure to all series, Peshbeen’s VAR can have, for example, one series with 2 lags and another with 1, 2, and 7 lags. This flexibility allows user to tailor the model to the specific characteristics of each series, improving forecasting performance.

Example for regime-switching multivariate forecasting using the MS-VAR model.

ms_var is the multivariate extension of ms_arr: it models several series jointly with vector-autoregressive dynamics while allowing the whole system to switch between a small number of hidden regimes (e.g. a calm regime and a volatile one). Like var, it accepts a per-series lag dictionary, so each target can have its own lag structure. After fitting you can inspect the inferred regimes with predict_states() (most-likely regime per timestep) and predict_proba() (full posterior over regimes), and read off information criteria via .aic, .bic, and .hqc.

We reuse the mv_train_data / mv_test_data split from the VAR example above.

from peshbeen.models import ms_var

# Two hidden regimes; per-series lag structure as with var.
msvar_model = ms_var(
    n_components=2,
    target_cols=['sales', 'marketing', 'advertising'],
    lags={'sales': 7, 'marketing': [1, 7], 'advertising': 5},
    cat_variables=['day_of_week', 'month'],
    categorical_encoder=ohe,
    n_iter=100,
    random_state=123,
)
msvar_model.fit(mv_train_data)

# forecast() returns a dict keyed by target column name (each value a length-H array)
msvar_forecasts = msvar_model.forecast(H=60, exog=mv_test_data[['day_of_week', 'month']])

print("Forecast keys:", list(msvar_forecasts.keys()))
print("AIC: {:.1f} | BIC: {:.1f}".format(msvar_model.aic, msvar_model.bic))

Multi-series forecasters

Multi-series forecasters train global machine learning models across collections of many individual time series (e.g. sales across 100 stores, demand for 1,000 SKUs, or patient admissions across multiple hospital wards) sharing a common schema indexed by an entity ID (id_col).

Comparing panel_forecaster vs. ml_multi_forecaster:

  • panel_forecaster (Global Pooled Panel):
    • How it works: Generates standard lag features (lag_1, lag_2, \dots) for each series independently, then vertically pools all samples into a single training table.
    • Potential advantages: Highly scalable to thousands of series; pools statistical power across related series (which helps prevent overfitting on short series); efficient memory footprint; handles cold-start series at inference time without architectural changes.
    • Considerations: Does not directly incorporate the historical lags of series A as input features to predict series B.
  • ml_multi_forecaster (Multi-Series with Cross-Series Interdependencies):
    • How it works: Extends multi-series pooling by capturing cross-series lag interdependencies across series, allowing one series’ temporal history to directly inform another’s forecast.
    • Potential advantages: Captures cross-series influences and substitution or complementary effects in multi-series collections.
    • Considerations: Requires aligning series across time, increasing feature dimensionality and training cost compared to independent panel pooling.

Global Panel Forecasting with panel_forecaster

In many practical settings — such as retail inventory, logistics, or healthcare operations — you need to forecast hundreds or thousands of distinct series simultaneously. Rather than fitting thousands of individual univariate models, panel_forecaster trains a unified global regressor across all series.

Here we use load_sales() to forecast multiple store-item series simultaneously:

from peshbeen.datasets import load_sales
from peshbeen.models import panel_forecaster
from lightgbm import LGBMRegressor
import matplotlib.pyplot as plt

# Load multi-series sales dataset
df = load_sales()

# Select 3 store-item series for demonstration
stores = ['store_01_item_01', 'store_01_item_02', 'store_01_item_03']
df_sub = df[df['store_item'].isin(stores)].copy()

# Split train and test temporally across all series
train = df_sub[df_sub.index <= '2025-12-31']
test = df_sub[df_sub.index >= '2026-01-01']

H = 14

# Initialize global panel forecaster
panel_model = panel_forecaster(
    model=LGBMRegressor(n_estimators=50, random_state=42, verbose=-1),
    id_col='store_item',
    target_col='sales',
    lags=[1, 7, 14]
)

# Fit on historical panel data
panel_model.fit(train)

# Generate forecasts for all series
panel_forecasts = panel_model.forecast(H=H)

# Plot actuals vs. panel forecasts for each series
fig, axes = plt.subplots(len(stores), 1, figsize=(12, 8), sharex=True)
for i, s in enumerate(stores):
    s_train = train[train['store_item'] == s]
    s_test = test[test['store_item'] == s].iloc[:H]
    axes[i].plot(s_train.index[-60:], s_train['sales'][-60:], label='Train History', color='#2b5c8f')
    axes[i].plot(s_test.index, s_test['sales'], label='Actual', color='black', linewidth=1.5)
    axes[i].plot(s_test.index, panel_forecasts[s], label='Panel Forecast', color='crimson', linestyle='--', linewidth=1.8)
    axes[i].set_title(f'Series: {s}', fontsize=11, fontweight='bold')
    axes[i].set_ylabel('Sales')
    axes[i].legend(loc='upper left')

plt.xlabel('Date')
plt.suptitle('Global Multi-Series Forecasting with panel_forecaster', fontsize=13, fontweight='bold')
plt.tight_layout()
plt.show()
